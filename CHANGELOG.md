- **2026-07-28** — **Seam identitas pengguna (Supabase-ready): mengubah "tinggal pasang auth" dari harapan jadi fakta yang bisa ditunjuk.** Target pemilik bukan membangun SaaS penuh, melainkan bisa berkata *"tinggal setup ini-itu, dan itu mudah"* secara JUJUR. Klaim itu cuma tahan-uji kalau seam-nya ADA — dan yang paling menentukan adalah identitas, sebab auth/tenancy/rate-limit/billing semuanya bertumpu pada "siapa ini". Dibangun sebagai SATU seam (`auth_service.py`) supaya sisa aplikasi cuma bergantung pada `Principal`, bukan Supabase/JWT:
  - **Dua mode dari env, bukan flag terpisah**: `SUPABASE_URL` kosong → **anonymous/dev** (aplikasi jalan penuh tanpa login, semua job milik "anonymous"; menjaga perilaku lama & repo tetap bisa dites $0). Terisi → **auth aktif**: frontend login ke Supabase, kirim JWT di `Authorization: Bearer`, backend verifikasi.
  - **Verifikasi menerima dua penandatanganan Supabase tanpa config tambahan**: HS256 (JWT Secret simetris, project lama) bila `SUPABASE_JWT_SECRET` diisi; ES256/RS256 (signing key asimetris, project baru) lewat JWKS yang diturunkan dari URL — tak perlu menaruh secret di backend. Jalur dipilih dari ADANYA secret, BUKAN dari `alg` di header token (mencegah "alg confusion").
  - **Isolasi data**: kolom `owner` di `jobs` (+ migrasi, pola `_MIGRATIONS`), `create_job(owner=...)`, dan cek `auth_service.owns` di GET status/download/diagrams. Job milik orang lain → **404** (bukan 403 — jangan bocorkan keberadaannya). Owner None (job lama / dibuat saat dev) → diizinkan (kompatibilitas mundur).
  - **Penjaga sesungguhnya di FastAPI, bukan RLS**: karena FastAPI ada di tengah (frontend tak konek langsung ke DB), otorisasi ditegakkan di query backend; RLS Supabase tak relevan di arsitektur ini.
  - **DB tetap SQLite** — belum perlu Postgres. Multi-instance nanti = arahkan `job_store` ke Postgres Supabase (modul sudah rata). Frontend login (supabase-js) = keping berikutnya, belum dibangun; seam backend bisa dites dengan token yang di-mint manual.
  - **368 test hijau** (+11: 8 auth_service HS256/dev/alg-confusion, 3 isolasi route end-to-end). `PyJWT[crypto]` masuk requirements. Biaya: **$0**.
